Installing the 4G HAT

Mounting and powering on the Waveshare SIM7600G-H on your Raspberry Pi 4 — no SIM card required for any of this.

Hardware: SIM7600G-H 4G HAT + Pi 4 Time: ~15 minutes Needs a SIM: No, not for this guide
Before you start Mount the HAT Antennas Software setup Power on Verify What's next

Before you start

What you'll touch, and what you won't

This guide gets the HAT physically mounted, powered on, and talking over AT commands — proving the hardware itself works. It stops short of getting it online, because that needs a SIM card you don't have yet. Nothing here needs one.

Power off first

Unplug the Pi completely before mounting or removing the HAT. HATs sit directly on the GPIO header — connecting one while powered risks shorting a pin or damaging the board.

Step 1

Mount the HAT on the GPIO header

  1. Find pin 1 on the Pi's GPIO header and pin 1 on the HAT's underside socket (the square-pad corner on each).
  2. Lower the HAT straight down over the header until it's fully seated.
  3. Press evenly on all four corners — don't rock it, that bends pins.

Step 2

Connect the antennas and the USB cable

  1. Screw the LTE antenna onto the connector labeled MAIN.
  2. Screw the GPS antenna onto the connector labeled GNSS.
  3. Leave AUX empty — it's for a diversity antenna that doesn't ship in the box.
  4. Plug the included USB-A–to–micro-B cable from the HAT into any free USB-A port on the Pi (not the Alfa adapter's port).

Step 3

Set up the serial port

Power the Pi back on and let it fully boot, then:

sudo raspi-config

Go to Interface Options → Serial Port:

  • "Would you like a login shell over serial?" → No
  • "Would you like the serial port hardware enabled?" → Yes

Finish, reboot, then install the terminal program you'll use to talk to the modem:

sudo apt update && sudo apt install -y minicom
Why "No" matters

Answering "Yes" to the login-shell prompt puts the Pi's own console on the same serial line the modem uses — the two fight each other and AT commands stop responding.

Step 4

Power on the module

Press and release the PWRKEY button on the HAT — about one second, not a long hold (holding 3–5 seconds shuts it back down if it's already on). Watch the NET LED: it should start blinking about once a second within roughly 10 seconds.

Step 5

Verify it's actually talking

Check it enumerated as a USB device and picked up serial ports:

lsusb                  # look for a Qualcomm or SimCom entry
ls /dev/ttyUSB*        # expect several — ttyUSB0 through ~ttyUSB4

Then talk to it directly:

sudo minicom -D /dev/ttyUSB2 -b 115200

Type AT and press enter — it should reply OK. Try ATI for the module's manufacturer/model info. Exit minicom with Ctrl+A then X.

If ttyUSB2 stays silent

Which port answers AT commands varies a little by unit — try ttyUSB0 or ttyUSB1 next. The module exposes several virtual serial ports at once (modem, diagnostics, GPS), only one of them is the AT command port.

You're done here when

lsusb shows the module, the NET LED is blinking, and AT gets back OK. That's the HAT fully installed and proven alive, independent of the SIM.

What's next

This was hardware proof, not internet

Everything above confirms the module itself works. Getting the Pi actually online through it is a separate, later step — Phase 1 in the Secure WiFi Box build guide — and needs the SIM card you don't have yet. Nothing in this guide was wasted work: the serial setup and the module being alive are exactly what Phase 1 builds on top of.
